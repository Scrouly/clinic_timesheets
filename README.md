# График работы врачей

Внутренняя система для составления, согласования и утверждения графиков работы врачей.
Сейчас в проекте есть вход, роли с правами по отделениям, справочники, графики по отделениям
и общий вид по кабинетам, проверки ошибок и расчёт норм часов. Согласование, печатные формы,
история изменений и выгрузка в 1С будут добавлены позже.

## Быстрый запуск (SQLite, для знакомства)

Нужен Python 3.12 или новее.

**Windows (PowerShell):**

```powershell
cd schedule_site
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
python manage.py migrate
python manage.py seed_demo
python manage.py runserver
```

**Linux / macOS:**

```bash
cd schedule_site
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python manage.py migrate
python manage.py seed_demo
python manage.py runserver
```

Откройте http://127.0.0.1:8000/ . Тестовые пользователи (пароль `demo-pass-2026`):

| Логин | Роль | Что видит |
|---|---|---|
| `admin` | Администратор | всё, включая «Образец сетки» и «Пользователи» |
| `hr` | Кадровик | все отделения, сводную, справочники |
| `head_diag` | По отделениям | диагностическое отделение, редактирование |
| `head_cons` | По отделениям | консультативные отделения, редактирование |
| `viewer` | Наблюдатель | все отделения, только просмотр |

Команда `seed_demo` работает только при `DEBUG=True` и нужна лишь для проверки интерфейса.
Она создаёт и выдуманный график на текущий месяц: врачей, кабинеты, смены, отпуск и одну
намеренную накладку в кабинете 117, чтобы было видно подсветку ошибок. Повторный запуск дублей не создаёт.

## Первая настройка (в admin)

Справочники графиков (`/admin/`) меняют только пользователи с флагом «Статус персонала» и ролью `admin` или `hr`.
Порядок первой настройки:

1. **Виды времени:** «Работа» (отметка «Рабочее время»), отпуск, больничный, командировка; код для 1С.
2. **Кабинеты:** название, порядок, «Можно делить» (операционная и подобные), «Показывать в общем графике кабинетов».
3. **Профессии** и правила длины смены для них (ставка от и до, минимум и максимум часов).
4. **Врачи** и их работа в отделениях: профессия, ставка, при необходимости свои границы смены.
5. **Нормы:** норма месяца на полную ставку, при необходимости норма профессии на месяц; производственный календарь.
6. **Графики** отделений на месяц. Статус и дату утверждения ставит кадровик или администратор.
7. **Доступ пользователей к отделениям:** на странице пользователя таблица «отделение и уровень» (просмотр или редактирование).

## PostgreSQL

В `.env` укажите строку подключения:

```
DATABASE_URL=postgres://ПОЛЬЗОВАТЕЛЬ:ПАРОЛЬ@СЕРВЕР:ПОРТ/ИМЯ_БАЗЫ
```

Для рабочей версии нужен именно PostgreSQL: на втором этапе проверка пересечения смен опирается на его возможности.
Создайте для проекта отдельную базу и отдельного пользователя.

## Устройство проекта

```
config/              настройки (base, dev, prod), адреса
apps/accounts/       пользователь с ролью и доступ к отделениям (DepartmentAccess)
apps/core/           отделения, меню, права, страницы, образец сетки
apps/schedule/       кабинеты, врачи, графики, смены, проверки, нормы, два вида графика
templates/           base.html (каркас), base_auth.html (вход), partials/, страницы
static/              css, js, шрифт Golos Text, img/brand (логотип CityClinic), внешних запросов нет
```

Главные решения:

- **Своя модель пользователя с первого дня.** Заменить её в готовом проекте очень трудно.
- **Вход обязателен везде.** Включён `LoginRequiredMiddleware`; открыта только страница входа.
- **Роли:** `admin`, `hr`, `viewer` видят все отделения (`admin` и `hr` ещё и редактируют). Остальные пользователи (роль `head`, подпись «По отделениям») получают доступ по отделениям: просмотр или редактирование отдельно для каждого. Ограничение накладывается на выборку данных (`DepartmentScopedMixin`), а не только на меню.
- **Один график, два вида.** Единственный источник данных это таблица смен `Shift`. Вид по отделению и общий вид по кабинетам (`apps/schedule/grids.py`) только читают её, поэтому правка в одном виде сразу видна в другом.
- **Проверки ничего не блокируют** (`apps/schedule/checks.py`): длина смены, врач в двух местах, смена в день отпуска, накладка в кабинете, норма часов. Ошибки подсвечиваются в ячейках и выводятся списком.
- **Меню собирается по роли** из одного списка `apps/core/navigation.py`.
- **Статика локальная.** Шрифт и иконки лежат в проекте, сайт работает без интернета.
- **Цвета статусов** повторяют легенду из текущих таблиц (составлен, внесён, на согласовании, изменения, ошибки, выходной, праздничный).

## Состав строк графика

Строки графика принадлежат месяцу: модель `ScheduleRow` (график, врач в отделении, ставка этого месяца, порядок).
Врач, добавленный в октябре, не появляется в других месяцах, а ставка, изменённая в октябре, не меняет норму
прошлых графиков. Сетки, проверки и нормы работают по строкам и их ставке.

- Заведующий с правом `edit` добавляет врача кнопкой «＋» между строками или внизу, убирает строку, меняет ставку и
  профессию, переставляет строки (меню «⋮» у строки). Выбирать можно только сотрудников из справочника; новых
  сотрудников, профессии и кабинеты заводят кадровик и администратор.
- Правила состава в `apps/schedule/rows.py` (добавить, убрать, переставить, изменить, скопировать состав), адреса в
  `apps/schedule/views_rows.py`, поведение в `static/js/grid-rows.js`.
- Запись смены сама добавляет строку, если врача в графике ещё нет (`Shift.save`).
- Новый график в admin получает состав предыдущего месяца отделения (ставки и порядок сохраняются), иначе действующих
  врачей отделения. Строки графика можно править и в карточке графика в admin.
- Удаление строки со сменами просит подтвердить их число; смены этого месяца удаляются, других месяцев нет.
- При обновлении запустите `python manage.py migrate`: миграция `0009_fill_schedulerows` создаст строки для уже
  существующих графиков.

## Оформление

Фирменные цвета и логотип CityClinic. Все цвета заданы переменными в блоке `:root` файла
`static/css/app.css`; в правилах ниже блока цветов быть не должно (это проверяет тест).

| Переменная | Значение | Для чего |
|---|---|---|
| `--brand` | `#0093CE` | заливки, значки, полоска активного пункта; **не для текста** (на белом 3,5:1) |
| `--brand-text`, `--brand-strong` | `#00709E`, `#005A80` | ссылки, основные кнопки, текст с акцентом (5,5:1) |
| `--brand-2`, `--tint` | `#A9DCF1`, `#E5FAFE` | светлые подложки, наведение, выбранный пункт |
| `--ink`, `--ink-2`, `--ink-3` | `#000B45` и светлее | основной, вторичный и подсказочный текст |
| `--focus` | `#2D8CFC` | только рамка фокуса |
| `--today` | `--brand-strong` | отметка сегодняшнего дня (столбец, строка, число в круге) |
| `--field-border` | `#76899A` | граница полей ввода, 3,6:1 на белом |
| `--accent-solid`, `--surface-inverse` | `#00709E`, `#000B45` | заливки под белый текст (кнопки, ссылка пропуска, круг дня) |
| `--text-xs … --text-2xl` | 12, 13, 14, 16, 18, 22, 26 px | шкала размеров текста, других размеров в правилах нет |
| `--st-*` | из легенды таблиц | цвета статусов, **не менять** |

Правила:

- Яркий `--brand` не ставим в `color:` и не используем в ячейках сетки: в легенде есть бирюзовый и
  голубой статусы, их легко спутать с цветом бренда.
- Статус никогда не показывается одним цветом: у плашки есть подпись, у накладки значок и рамка.
- Зелёный остаётся только статусом «Утверждён».
- Токен используется только по своей роли: `--brand-text` для текста, `--accent-solid` для заливок; `--focus` только для фокуса.
- Закреплённые области сетки (шапка, колонка врача, итоги) не должны закрывать элемент в фокусе: для этого у
  `.grid-wrap` заданы `scroll-padding-*` (модификаторы `--by-day` и `--sums`). Меняете ширину колонки или высоту шапки,
  меняйте и отступ.
- Подсветка по наведению только внутри `@media (hover: hover)`; то, что открывается по наведению (кнопка «+»),
  на сенсорных экранах показывается всегда.
- Кольца и рамки состояний делаем `outline` или `border`, а не `box-shadow`: тени пропадают в режиме высокой контрастности.
  Для `outline: none` обязателен прозрачный контур `outline: 2px solid transparent`.
- Высота экрана `100vh` всегда с запасным `100dvh`; у прокручиваемых панелей `overscroll-behavior: contain`.
- Радиусы: `--radius` 6px (кнопки, поля), `--radius-lg` 8px (панели, таблицы), `--radius-sm` 3px (ячейки сетки).
- Логотип: `static/img/brand/logo.svg` (знак и слово), `logo-mark.svg` (только знак), PNG для писем и документов.
  SVG получен трассировкой из PNG; если клиника пришлёт исходник, файлы заменяются без правок шаблонов.

Что проверяют тесты: контраст всех текстовых пар и плашек статусов не ниже 4,5:1 (`test_css_tokens.py`),
на каждой странице один `h1`, подписи таблиц, значки с `aria-hidden`, имена у кнопок-значков (`test_a11y.py`);
число запросов к базе не растёт вместе с числом смен и врачей (`test_query_counts.py`). Линтер: `ruff check .` (настройки в `pyproject.toml`).

## Как добавить страницу

1. Напишите view. Для ограничения по ролям используйте `RoleRequiredMixin` с `allowed_roles`.
2. Добавьте адрес в `apps/core/urls.py` (или в `urls.py` нового приложения).
3. Добавьте строку в `NAV_ITEMS` в `apps/core/navigation.py`: подпись, имя адреса, роли, группа, иконка.
4. Шаблон начните с `{% extends "base.html" %}` и заполните блоки `page_title`, `page_lead`, `page_actions`, `content`.

Страница с сеткой, где смену правят на месте: подключите `partials/_side_panel.html`, а ссылкам на форму
добавьте атрибут `data-panel-link`. Форма откроется справа без ухода со страницы, без JavaScript пользователь
попадёт на обычную страницу формы. Тот же адрес отвечает коротким фрагментом на запрос с заголовком
`X-Requested-With: fetch` (см. `ShiftFormMixin`); права проверяются как и раньше.

Готовые части шаблонов: `partials/_field.html` (поле формы), `_empty.html` (пустое состояние),
`_pagination.html` (страницы), тег `{% status_badge "approved" %}` (плашка статуса), фильтр `|hours` (часы с запятой).
